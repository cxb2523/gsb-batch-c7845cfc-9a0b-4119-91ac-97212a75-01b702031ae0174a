GCP Data Engineering and AI: Reference Document Corpus

== SECTION: BigQuery Billing and Cost Optimization ==
BigQuery on-demand billing charges $5 per terabyte of data scanned. Queries against partitioned tables scan only the relevant partitions, which can reduce costs by 90% or more on time-series datasets. Clustered tables further reduce scan volume by co-locating rows that share the same cluster column values. The INFORMATION_SCHEMA.JOBS_BY_PROJECT view exposes bytes billed, slot milliseconds, and query text for every job, enabling cost attribution per team or user. Reservations and slot commitments convert on-demand billing to a flat-rate model; Autoscaler within reservations dynamically adjusts capacity to actual demand.

== SECTION: IAM and Security on GCP ==
Identity and Access Management (IAM) on GCP uses a principal-role-resource model. Principals are Google accounts, service accounts, groups, or domains. Roles bundle permissions; predefined roles (e.g., roles/bigquery.dataEditor) are maintained by Google, while custom roles allow least-privilege definitions. Conditions add attribute-based access control, restricting access by time, IP range, or resource tag. Workload Identity Federation enables external identities (GitHub Actions, AWS, Azure) to impersonate GCP service accounts without static keys. Audit logs in Cloud Logging record Admin Activity, Data Access, and System Event audit trails for compliance requirements.

== SECTION: Cloud Run Deployment Patterns ==
Cloud Run deploys stateless containerized workloads that scale from zero to thousands of instances based on HTTP traffic. Minimum instances can be set to avoid cold starts in latency-sensitive APIs. CPU allocation can be set to "always on" for background processing workloads that use CPU outside request handling. Cloud Run Jobs handle non-HTTP tasks such as database migrations, batch exports, and scheduled data processing. Sidecar containers in Cloud Run support co-located agents like logging collectors or authentication proxies. Traffic splitting between revisions enables blue-green and canary deployments with zero downtime.

== SECTION: Pub/Sub Streaming Architecture ==
Cloud Pub/Sub is Google's fully managed asynchronous messaging service. Publishers write messages to topics; subscribers consume messages from subscriptions. Push subscriptions forward messages to an HTTP endpoint; pull subscriptions allow consumers to fetch messages at their own pace. Message ordering is guaranteed within a single ordering key across a subscription. Dead-letter topics capture messages that fail processing after the configured maximum delivery attempts. Pub/Sub Lite is a lower-cost alternative with zonal storage for high-throughput pipelines where global availability is not required.

== SECTION: Vertex AI Model Serving ==
Vertex AI Endpoints host deployed model versions and serve online predictions via REST or gRPC. Traffic splitting across model versions enables A/B testing and canary rollouts. Dedicated endpoints provide reserved compute; shared endpoints are cost-effective for bursty or low-QPS workloads. Vertex AI Batch Prediction submits large prediction jobs that process millions of inputs asynchronously from Cloud Storage. Model monitoring detects feature skew and prediction drift by comparing live traffic distributions to a training baseline. Explainability methods—SHAP, XRAI, integrated gradients—attribute model predictions to input features for debugging and compliance.

== SECTION: Dataflow and Apache Beam ==
Cloud Dataflow is Google's managed Apache Beam runner. Beam pipelines express transformations as a directed acyclic graph of PCollections and PTransforms. The same pipeline code runs in batch mode (bounded PCollections) and streaming mode (unbounded PCollections) without modification. Windowing strategies—fixed, sliding, session—group streaming elements by time for aggregation. Watermarks track event-time progress; late data triggers handle records that arrive after the window closes. Dataflow Flex Templates package pipeline code in Docker containers, enabling parameterized deployments with custom base images and dependencies. The Dataflow Prime autoscaler optimizes worker count and resource allocation dynamically during execution.

== SECTION: Document AI Processor Types ==
Document AI provides specialized processors for different document types. The OCR Processor extracts raw text from scanned PDFs and images using Google's Vision technology. The Form Parser identifies key-value pairs and tables in structured forms, enabling digitization of paper workflows. The Invoice Parser extracts structured entities—supplier name, total amount, line items, due dates—from supplier invoices, integrating with ERP and AP automation systems. The Layout Parser produces layout-aware chunks that respect document structure (headings, sections, tables) and are optimized for RAG ingestion pipelines. Batch processing via GCS handles volumes above the synchronous 15-page limit and large-scale document archives.

== SECTION: FAISS and Vector Search ==
FAISS (Facebook AI Similarity Search) is an open-source library for efficient similarity search over dense vector embeddings. IndexFlatIP performs exact brute-force inner-product search and returns perfect recall at O(n) cost per query. IndexIVFFlat partitions the vector space into Voronoi cells and searches only the nearest cells, delivering approximate results in sub-linear time at the cost of some recall. HNSW (Hierarchical Navigable Small World) graphs offer high recall with logarithmic query time and are the default index type in many production vector stores. FAISS runs entirely in process memory, making it suitable for single-machine RAG applications and offline batch embedding jobs where no external infrastructure is required.
